Measured over three cold-agent trials of `wake install`: the trigger fired 3/3, but only 2/3 filed in the right place. The third created its issue inside an unrelated project that happened to be in the space.

The cause is a real gap, not a prompt problem. `space.repos` maps a repo to a **space**. Nothing maps it to a **project**. So an agent matches the space deterministically and then has to *guess* among that space's projects — and prose telling it to create one when none matches is advice, not a mechanism.

Fix: record the repo on the project too, so `list_spaces` can hand back the project for a given remote and remove the judgment entirely. `wake connect` would set it; an unclaimed repo would still say "create one".
